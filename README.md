# CS305-SNHU

In CS305, I learned the basics of secure software practices, using the ficticitous Artemis Financial client and software as a practice ground. Artemis Financail needed a secure API for their use in integrating their data stores with their digital business more intensely. However, Artemis Financial provides financial advice to their clients, and therefore needs to make sure all communications and data stores possess top notch security measures. Even if an outside force were just to be able to read Artemis Financial's clients' information, it could be catatstrophic. Artemis Financial needed me to provide secuirty advise and reccommendations to make their software safe and secure to use for this purpose.

I first conducted a static test of the code, where I found numerous best practices violated, and some errors in the code which would fail silently and likley cause the program to function unpredictably. I proposed fixes for these issues. It is important to make sure the underlying code base is foundationally sound before adding additional secuirty measures, as buggy or glitchy code can create security vulnerabilities during runtime, which are much more difficult to identify and address. Furthermore, a company with a healthy codebase will make future updates and functional additions much easier to implement without introducing more bugs or glitches. A company with a healthy code base for its software runs more smoothly.

The most difficult part of the vulnerability assessment was indicating how to fix each issue. There are 100s of known secuity vulnerabilities in Artemis Financial's current software, making an action plan to fix each issue seem daunting. However, the Maven Dependency Check Report made it much easier to identify which dependencies caused what security vulnerabilities, and therefore hwo to target fix each dependency to fix the vulnerabilities it caused.

To increase the security of Artemis Financial's software, I reccommended an encryption technique for their stored data, and integrated checksum verification. I also addressed the issues with their codebase, and then checked to make sure no new vulnerabilities were created by my additions. This addition mainly was the Hash Controller class, which facilitates the checksum verification process using their underlying software.
